# Нейронет — десктопный анализ сессии

Локальное приложение с одним фронтальным видео, сигналами BioRadio и стенограммой на общей временной шкале. Интерфейс сделан на PySide6, видео воспроизводится через Qt Multimedia. HTTP-сервер и браузер для работы не нужны.

## Установка и запуск

```bash
cd /Users/dumbcl/neuronet/neuronet_lab
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m neuronet_lab.desktop
```

На macOS после установки можно также запустить приложение двойным щелчком по `Запустить Нейронет.command`.

На Windows окружение активируется командой `.venv\Scripts\activate`. Для базового просмотра, импорта CSV и ручной стенограммы достаточно `pip install -r requirements-core.txt`. Дополнения для анализа видео и расшифровки речи ставятся через `requirements-video.txt` и `requirements-audio.txt`.

Qt Multimedia поддерживает воспроизведение через системные кодеки и свой мультимедийный движок. Если конкретное видео не открылось, попробуйте MP4/H.264. Исходное видео копируется в `data/sessions/<id>/`; CSV разбирается в массивы NumPy внутри той же папки. Данные не отправляются в сеть. При первом запуске **автоматической** расшифровки faster-whisper может скачать модель `small` в локальный кеш.

## Работа в приложении

1. Создайте сессию, добавьте фронтальное видео и экспорт BioRadio CSV. Импорт большого CSV выполняется в фоновом потоке.
2. Укажите для каждого файла метки начала покоя, начала и конца разговора и конца записи. Время вводится от начала соответствующего файла: секунды или `мм:сс`. Для видео можно взять время из текущего положения плеера. Совпадающие метки выравнивают записи кусочно-линейно; одна метка задаёт постоянный сдвиг.
3. Управление воспроизведением находится над видео: пуск/пауза, переход на ±5 секунд и ползунок времени. Область под видео прокручивается от меток синхронизации до отдельных увеличенных графиков BioRadio. После остановки или перемещения курсора рядом с плеером показываются текущие признаки и краткие показания BioRadio.
4. Во вкладке «Стенограмма» добавьте реплики вручную или запустите автоматическую расшифровку. Укажите говорящего как «Интервьюер» или «Респондент», проверьте текст и сохраните.
5. Во вкладке «Интервал» задайте начало и конец, затем рассчитайте показатели ЭКГ, ФПГ, дыхания, GSR, rPPG, позы и речи. Во вкладке «Разметка» можно сохранить название фрагмента и экспертную метку «база / правда / ложь».

Импорт поддерживает обычный CSV, разделитель `;`, десятичные запятые в кавычках и предоставленный вариант BioRadio, где десятичная запятая одновременно служит разделителем CSV. Структура проверяется отдельно для каждой строки, в том числе когда GSR или другой аналоговый канал записан целым числом. Неоднозначные строки остаются пропусками с исходным временем; их число и пропуски по каналам записываются в `signal_meta.json`. Для восстановления неэкранированных запятых используются целочисленные поля HR/SpO₂/Event и предел аналоговых значений ±2³¹. Обычного CSV и значений в кавычках эти ограничения не касаются; экспорт с `;` или кавычками предпочтительнее.

Названия датчиков могут отличаться: `Flow Rate Sensor 1`, `Heart Rate PulseOx1`, `PPG PulseOx1`, `SpO2 PulseOx1` распознаются как те же каналы, что и `Flow Rate temp` / `… pulse`. Имя исходного файла и заголовки сохраняются в метаданных импорта. Если ни одно значение измерительных каналов прочитать не удалось, импорт завершается ошибкой до замены файлов сессии. Число строк с ошибками отображается рядом с информацией о BioRadio.

Для старой сессии повторно импортируйте исходный CSV. Во вкладке «Стенограмма» кнопка **«Пересчитать акустику по видео»** обновляет измерения на всей длине существующих реплик, сохраняя тексты, говорящих, синхронизацию и разметку. Повторная автоматическая расшифровка для этого не требуется. Покадровые акустические показатели сохраняются отдельно в `audio_features.npz`.

### Определения показателей

- Ответ определяется как последовательность реплик респондента до смены говорящего. Задержка считается от конца предшествующей последовательности реплик интервьюера до начала ответа, включая контекст вне выбранного интервала. Отрицательная задержка означает наложение речи. Это приближение: короткая вставка интервьюера делит ответ.
- Полная длительность ответа включает паузы между его репликами. Темп в выбранном интервале делит количество слов на попавшую в интервал длительность ответов, включая эти паузы. Слоги оцениваются по числу гласных. При частичном пересечении реплики слова считаются по временным меткам слов; если их нет, темп недоступен. Редактирование текста или границ сбрасывает устаревшие временные метки слов.
- RMS и спектральный центр считаются по всей реплике; для произвольного интервала используются окна 50 мс с шагом 20 мс, полностью попавшие в речь респондента. F0 — медиана кадров с достаточной энергией и периодичностью в диапазоне 70–400 Гц; отдельно показывается IQR. На тишине и непериодическом шуме F0 отсутствует. Это оценка основного тона, требующая проверки на реальной речи.
- Основная ЧСС rPPG интервала включает только оценки, **всё окно расчёта которых находится внутри интервала**. «rPPG с учётом предыстории» показывает контекстные оценки, использующие до 12 секунд до текущего кадра. `rppg_coverage` — доля временных точек с подходящим окном, а не точность метода. У старого кеша границы окон восстанавливаются по периоду обнаружения лица.
- Скорость смещения рамки лица выражается в ширинах лица в секунду и включает дрожание детектора. Новая видеообработка учитывает соотношение сторон кадра для наклона корпуса и движений конечностей; единица скорости конечностей — высоты изображения в секунду. Для старого кеша интерфейс предлагает повторить анализ видео. Наклон корпуса остаётся двумерной оценкой.
- Вычисления сохраняют числовую точность; округление выполняется при отображении.

## Границы результата

- ВСР (SDNN, RMSSD, LF/HF) рассчитывается от 120 секунд при достаточном числе пригодных интервалов. Детектор не соединяет участки через пропуски; скрининг RR отбрасывает интервалы вне 0,3–2 с и отклонения более 25% от локальной медианы. Для ВСР допускается не более 5% отброшенных интервалов; RMSSD использует только соседние пригодные интервалы. Для спектра сохраняются исходные времена ударов, единичные исключения интерполируются; большие разрывы блокируют расчёт. Эти эвристики не заменяют проверку пиков на исходном сигнале.
- Спектр RR — односторонняя периодограмма с окном Hann после интерполяции RR в миллисекундах на сетку 4 Гц. Плотность выражена в мс²/Гц, LF (0,04–0,15 Гц) и HF (0,15–0,4 Гц) — в мс². `total_power` содержит сумму LF+HF с явной границей 0,04–0,4 Гц. ULF/VLF остаются недоступны: окна лабораторной недостаточны для надёжной оценки этих диапазонов. Ограничения длительности описаны в [рекомендациях SPR, 2024](https://doi.org/10.1111/psyp.14604).
- Видеоанализ использует OpenCV; при наличии MediaPipe включается модель позы из `models/`. При потере лица или видимых частей тела соответствующие значения остаются пустыми.
- Автоматическое разделение двух голосов приблизительное. Метки и стенограмму нужно проверить вручную.
- Для автоматической расшифровки используется локальная модель faster-whisper; звук декодируется напрямую через PyAV, в том числе с текущими версиями PyAV, где отсутствует параметр `metadata_errors`.
- **Вероятность лжи не вычисляется:** для неё необходимы размеченная выборка, обучение и отдельная проверка модели. Экспертная метка интервала не является прогнозом.

## Структура

### Размеченные сессии и датасет

В проверенных сессиях `session.json` содержит плоский список `answers`: один элемент — полный ответ респондента, включая внутренние паузы. У него есть стабильный `id`, `participant_id`, границы `start/end` в секундах видео, экспертный `label`, ссылки `turn_ids` на текст, границы вопроса, `internal_pauses` и ссылки `source_annotation_ids` на исходную разметку участника. Поле `episode` связывает ответ с вопросом и ожиданием: хранит границы трёх этапов, идентификаторы реплик вопроса и замечания к времени. Кандидаты для бинарного датасета имеют `dataset_eligible=true`; это наличие определённого класса, а не подтверждение качества всех сигналов. Для выгрузки нужны также проверка синхронизации и качества признаков. `annotation_sources` хранит исходные интервалы и основания изменения метки.

`annotations` остаётся разметкой для просмотра: молчание может быть «базой», а `answer_id` связывает внутреннюю паузу с полным ответом. В датасете **одна строка соответствует одному эпизоду с одним ответом**; участник сохраняется для разделения обучения и проверки. Нельзя экспортировать каждый фрагмент тишины как независимый правдивый/лживый ответ. После ручного изменения границ, говорящих или меток `answer_review_required=true` означает, что перед выгрузкой связи ответов нужно перепроверить. Переименование интервала и пересчёт акустики этих связей не меняют. Границы эпизода при каждой выгрузке заново определяются по текущим связям реплик и интервалам покоя.

Во вкладке **«Разметка» → «Датасет для исследования»** введите имя и нажмите **«Сформировать датасет»**. Сохранённые интервалы используются целиком для текущей сессии; выбор фрагмента плеера не ограничивает выгрузку. Текст стенограммы и метки синхронизации из полей интерфейса сохраняются перед расчётом. Расчёт идёт в фоне, без повторного распознавания речи и видео.

Для новой сессии или после изменения разметки сначала нажмите **«Сформировать полные ответы из интервалов»** в этом же блоке. Кнопка сохраняет текущие таблицы стенограммы и интервалов и метки синхронизации, затем создаёт `answers` и эпизоды. Роли, тексты, времена и экспертные метки автоматически не исправляются. Для новых групп объединяются последовательные реплики респондента между репликами интервьюера; уже существующие корректные смысловые группы сохраняются, в том числе с коротким вмешательством интервьюера. Без заранее заданной группы программа не определяет по смыслу, было ли вмешательство новым вопросом: проверьте роли и исходные интервалы перед формированием.

Класс берётся из **текущей разметки**: вся речь полного ответа должна быть покрыта одним классом «правда/ложь». Внутренние паузы из разрывов реплик, времён слов, прежних ответов и явно заданной внутренней «базы» сохраняются отдельно; база между одинаковыми классами внутри ответа считается размеченной паузой. База по краям ответа не присоединяется к его классу. Смешение правды и лжи, непокрытая речь, явные участки «Без метки», пересечения ответов и другие сомнения исключают ответ из экспорта и показываются под кнопкой. Интервалы, не пересекающие реплики респондента, также перечисляются в замечаниях. «База» целиком остаётся вне бинарного датасета.

Повторное формирование сохраняет идентификаторы существующих корректных ответов и историю экспертных меток в `annotation_sources`; при изменении метки добавляется новый источник без удаления прежнего. Перед записью создаётся копия `session.json` и отчёт в `data/sessions/<id>/reviews/`. При замечаниях уточните интервалы/роли и сформируйте ответы повторно. Результат автоматического формирования требует проверки человеком; он не определяет правдивость по содержанию и не запускает ASR или анализ видео.

В папке `data/sessions/<id>/` появятся `<имя>.csv` и `<имя>.metadata.json`. При повторной выгрузке добавляется номер `(2)`, `(3)` и так далее. CSV в UTF-8 с BOM, разделитель — запятая, десятичный знак — точка; в Python: `pandas.read_csv(path, encoding="utf-8-sig")`. Для объединения участников достаточно объединить строки одинаковой схемы CSV.

- Одна строка соответствует эпизоду **вопрос → ожидание → полный ответ**: `target=0` — правдивый ответ, `target=1` — ложный ответ. Вопрос и ожидание используются как контекст этого ответа. База, уточнения и непроверенные ответы не создают отдельные строки; список исключений находится в JSON. При устаревших связях полных ответов или повреждённых ссылках экспорт сообщает ошибку.
- Сохраняются идентификаторы участника, сессии и ответа, границы в видео и BioRadio, текст ответа и вопроса, паузы, речевые и акустические показатели, ЧСС/дыхание/GSR/SpO₂, доступные показатели ВСР, rPPG и движения. Значения сохраняются без округления. Единицы и список числовых признаков находятся в JSON.
- Отдельные поля содержат покрытие сигналами, качество детекции, метод расчёта, состояние синхронизации и замечания. При отсутствии синхронизации BioRadio его показатели пусты; речевые и видеопризнаки сохраняются. Предварительная синхронизация явно помечается. Пересекающиеся времена вопроса и ответа оставляют задержку пустой.
- Недоступные признаки остаются пустыми: ВСР требует достаточной длительности, rPPG — окна внутри соответствующего этапа. rPPG всего эпизода может быть доступен, даже если на одном ответе окно слишком короткое. Оценки rPPG с предысторией вне измеряемого окна и вероятность лжи в признаки не включаются. Данные не нормализованы по базе; исходные базовые интервалы и синхронизация записаны в JSON для дальнейшей обработки. Метки, идентификаторы и текст вопросов нельзя автоматически включать в признаки модели; разделять обучение и проверку нужно по участникам.

Схема CSV версии **2** добавляет:

- `episode_start_seconds`, `episode_end_seconds`, `episode_duration_seconds` — границы и длительность всего эпизода;
- `question_phase_start_seconds/end_seconds`, `waiting_start_seconds/end_seconds`, `answer_start_seconds/end_seconds` — границы отдельных этапов; ожидание нулевой длины хранится как 0 секунд без расчёта сигналов;
- `question_contact_*`, `waiting_contact_*`, `episode_contact_*` и соответствующие `*_video_*` — показатели BioRadio/видео на каждом этапе и всём эпизоде;
- `delta_answer_minus_question_*` — значение во время ответа минус значение во время вопроса, когда доступны оба;
- отдельные границы времени BioRadio, покрытие и качество для каждого окна; `episode_status` и `question_overlap_seconds` описывают ограничения разметки.

Столбцы без этих префиксов (`contact_*`, `video_*`, `speech_*`, `video_start/end_seconds`, `signal_start/end_seconds`) сохраняют смысл схемы 1: показатели и границы **самого полного ответа**. Речевые показатели всегда относятся только к респонденту в ответе. `question_start/end_seconds` хранит исходные границы связанного блока интервьюера; фактическое окно измерения — `question_phase_start/end_seconds`.

Вопрос ограничивается предыдущим ответом и отмеченным покоем, поэтому инструкция перед двумя минутами покоя не расширяет первый эпизод на эти две минуты. При пересечении времён ASR вопрос ограничивается началом ответа; ожидание и задержка остаются пустыми. При отсутствии вопроса сохраняется эпизод только с ответом и явным замечанием. Послеответная тишина и следующий вопрос не добавляются.

Журнал проверки сессий от 21.10.2026: `data/reviews/session_review_20261021_200459/review_report.md`.

Для проверки новой сессии другой LLM используйте самостоятельный промпт [`prompts/review_new_session.md`](prompts/review_new_session.md). Перед отправкой заполните пути, участника и его индивидуальные условия правды/лжи.

- `neuronet_lab/desktop.py` — нативное окно, плеер, графики и редакторы.
- `neuronet_lab/session.py` — хранение сессий и синхронизация файлов.
- `neuronet_lab/bioradio.py` — потоковый импорт и выборка CSV.
- `neuronet_lab/analytics.py` — показатели интервала.
- `neuronet_lab/dataset.py` — выгрузка полных ответов и признаков в CSV с описанием в JSON.
- `neuronet_lab/episodes.py` — границы вопроса, ожидания и полного ответа.
- `neuronet_lab/answers.py` — формирование полных ответов по ролям и экспертным интервалам.
- `neuronet_lab/media.py` — лицо, поза, rPPG и речь.
- `models/haarcascade_frontalface_default.xml` — детектор лица из [официального репозитория OpenCV](https://github.com/opencv/opencv/blob/master/data/haarcascades/haarcascade_frontalface_default.xml), используемый при отсутствии XML в пакете OpenCV.
- `tests/` — проверки импорта, синхронизации и окна приложения.

Проверка: `python -m unittest discover -s tests -v`.
